# 决策落盘为单一权威来源

**Trigger**：代码/文档注释里引用了一串决策编号，而那份「权威文件」里查不到；或决定目前只活在对话中。

**核心判据**：只存在于对话、从未落盘的决策比没有决策更坏——查编号的人顺着编号去找只会扑空。

## Steps

1. **指定唯一权威文件**并在其开头写死一句：引用到查不到的编号即为错，以本文件为准。
2. **从权威出处批量回填**（如架构「决策 → 机制」对照表），不要从代码注释反推。
3. **保留可重跑脚本**（`scripts/backfill_*.py`）入库，使回填可重复。
4. **落盘只抄原文，不新增解释**——新增解释会引入无法反查的主张。
5. **机械校验并归零悬空引用**：统计「被引用的编号集合 − 实际存在条目集合」。
6. **修订既有决策时两处都做**：旧决策正文就地标注「已废弃/被谁修订」+ 修订关系索引登记一行；且**修订前先回查被修订方自己的依据**。

## Pre-conditions / inputs

- 权威出处（对照表、材料原文），可逐字复制
- 既有决策条目与其原始依据，供修订前回查
- 编号提取方式：按行首/首列取值，注意一行可声明多个编号

## Failure modes / caveats

- **决策记录不接受未验证的断言**：靠不住的依据比没依据更坏，因为它让人省掉验证。凭印象写下的「已实测」应立即实测并改正。
- 提取编号时只取首个会漏条目；用全文正则会把机制说明里的「引用」也算进来。
- 批量回填后必须**逐字比对**确认未篡改，只看自己的生成结果不算校验。
- 把「文档声称的测试/依据其实不存在」当空承诺看待，比不写更糟（见 审计的主要工作量在核对承诺，不在读代码）；修完这类落差后，值得把它做成会红的断言（见 把不变量写成会红的断言，并验证断言本身）。
- 落盘后仍只宣告「要落盘」而无文件产出，属同一根因的执行侧，见 把承诺压缩成「一句话 + 立刻写出文件」的绑定动作。

## Sources

- 这一流程的两条硬规则与「先回查被修订方自己的依据」出自 政通项目设计冻结纪要 的收官体检节：其中记录新增「修订关系索引」，并在维护约定里确立「就地标注 + 索引登记」两处都做的规则。
- 同一纪要记录了 81 条悬空引用的回填全过程——权威文件当时只有六条而代码引用了 87 处，根因正是决策只存在于对话中；修法是从对照表逐条回填、保留可重跑脚本、只抄原文不新增解释，并记录下提取编号时「一行可声明多个编号」的坑。
- 「靠不住的依据比没依据更坏」与「记下来不等于改掉」同见 当日项目纪要，后者说明写下判据并不等于默认动作改变，落盘规则本身也需要执行侧的绑定机制。
