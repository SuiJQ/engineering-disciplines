# 宣告代替动作：用绑定动作取代口头决心

**Trigger**：发现自己正在（或已经）输出「写正文。」「现在写出。」「继续写第五道。」这类宣告却没产生任何文件——尤其是刚刚承诺过「不再逐步汇报、一次写完」之后。

**核心判据**：写下判据、承诺、口头决心都不构成对默认动作的改变。宣告轮只有同时携带**产出物路径**才算完成，否则按未完成处理。

## Steps

1. **识别复发**：数一下今天已发生几次。此模式高发于「刚承诺改进」之后的下一轮——承诺本身不改变默认动作，别把复发当成偶发。
2. **把范围判据前置声明**：先写清这一轮锁什么、不锁什么（只锁已存在的确定性，不去测尚未实现的阶段）。范围不清会被「等写完再…」无限拖延。
3. **压缩承诺为一句 + 一个路径**：宣告那一轮必须同时给出产出物路径；只有句子没有路径的宣告，视为未完成。
4. **立刻写出文件**，不拆成多轮汇报。
5. **自检**：若某轮只有句子没有文件，直接重做该轮而不是继续汇报。

## Pre-conditions / inputs

- 待产出的目标（文件路径）
- 已前置声明的范围判据

## Failure modes / caveats

- 「记下来不等于改掉」：承诺本身是高危时刻，最容易在承诺后立刻复发。
- 长任务尤其容易退化为逐步汇报；一次性写完的承诺要绑定文件路径才有效。
- 这与 审计的主要工作量在核对承诺 是同一病灶的两面：那边是**读**别人的空承诺（文档说 A、代码做 B），这边是**制造**空承诺。

## Sources

- 这一对策来自 当日项目纪要：记录同日三次复发「宣告代替动作」，且发生在刚承诺「不再逐步汇报、一次写完」之后，并给出「写下判据不等于改变默认动作，需要一句话 + 立刻写出文件的绑定机制」这一元教训。
