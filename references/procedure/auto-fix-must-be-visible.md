# 自动修复要「动得可见」，门禁不该在检查途中改被检查的东西

**Trigger**：要给检查/修复工具加 `--fix` 这类会写盘的分支，或排查「工具悄悄改了代码却没人知道」时。

## Steps

1. **默认只读**：检查命令默认不碰工作区（`ruff format --check`），真改必须走显式开关（`--fix`）。报告而不动手是默认形态。
2. **判定不信退出码**：门禁成败按输出内容数（如 `0 errors`）判定。退出码可被 warning、管道里的 `tee`、shell errexit 提前退出绕掉；判据的载体应是那句人说没说过的结论，见 把不变量写成会红的断言，并验证断言本身。
3. **给写盘动作配可见性守卫**：修复前后各拍一次工作区快照，取差集点名「本轮原本干净、修复后变脏」的文件，并以非零码停下。守卫自己也要能被证伪成红，见 判据要断言可观测的行为差异，不断言表面特征或词面。
4. **如实写边界**：这类差集守卫只抓「修完仍脏」，修回干净时不响；不响就不能宣称全覆盖，把已知盲点写进脚本注释而不是省略。
5. **逐分支真跑**：同一命令的每个参数分支都会各自腐烂——把 `--fix` 传给不支持它的子命令，一用就崩却长期没人发现，因为大家都跑默认那条。
6. **还原精确到改动点**：可逆操作（`git reset --hard`、`git checkout`）的粒度是整个文件，会连带抹掉同文件刚写的新改动、把已删代码一起还原；改用逐改动点还原，并在还原后立刻跑全量测试，与 证伪前拍改动前备份，还原后重跑全量 是同一条纪律的两面。
7. **拿不准是不是纯格式重排时用语义比对**：`ast.dump` 逐文件比语法树证明零逻辑改动，不靠 diff 行数判断（换行重排同样产生大量 diff）。

## Pre-conditions / inputs

- 一个能取工作区快照的手段（如 `git status --porcelain`），否则第 3 步无从取差集
- 显式的写盘开关，而不是靠环境或调用方自觉
- 一个可计数的输出格式，否则第 2 步无法按内容判定

## Failure modes / caveats

- **门禁在检查途中改变被检查的东西**：同一次运行的不同阶段看到的不是同一份代码；中途停下时工作区停在「已改文件但未检查」的中间态，报错行号还对不上格式化后的文件。
- **自动修复会破坏生产代码**：`--fix` 把代码搬进别的函数体、删掉真实调用，要到类型检查才报未定义名；`--fix` 只用于机械可修项，类型与语义错误一律人工看上下文。
- **命令被每轮记成「全绿」但从没真跑过**：与 判据查「结果怎么来的」不只查「结果长什么样」 同型；也要防另一头——噪声与误报堆积的门禁会被忽略，而被忽略等于没有，见 未接线排查：扫四种形状、逐条人工定性、判据先注入证伪。
- 回滚抹掉同文件新改动且不报错，症状是「刚写的守卫凭空消失」。

## Sources

- 可见性三件套（默认只检查不改、按输出内容判 0 errors、`--fix` 前后拍工作区快照取差集点名变脏文件并非零码停下）及其边界声明，来自 2026-10-03 日记 中排查自动修复改动生产代码根因并新增那条守卫的记录，同一记录还给出把 `--fix` 传给不支持它的格式化子命令导致一用就崩、却长期无人走到的老 bug。
- 另两条同源教训的现场证据在 正听项目完整工作记录（2026-10-02 夜 ～ 2026-10-03）：自动修复两次把生产代码搬错函数体、删掉真实调用，`git reset --hard` 与 `git checkout` 抹掉同文件刚写的守卫改动，格式化回滚时以逐文件语法树比对证明零逻辑改动。
