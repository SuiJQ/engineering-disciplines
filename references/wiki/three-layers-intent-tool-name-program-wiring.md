# 能力要真正发生：意图、工具名、程序接线三层齐备

**一句话**：要让模型真的做出某个动作，只在提示词里说「要做什么」不够；三层须同时齐备——提示词要求必做、提示词写明用哪个工具、程序能把请求送出去并把结果拿回来。

## 三层与各自的断法

- **意图层**：提示词要求必做/必问，缺则不得动笔。
- **工具名层**（最易被跳过）：只说「要问」不说「用什么问」，模型无从下手。
- **接线层**：装配根把回调或端口真的传进来，能把问题送出去并拿回答案。

缺中间层时，另两层的投入全部空转——线接好了、意图也写了，模型仍然不会问。

## 「没有回答者就没有答案」应是结构性保证

无界面运行时确实没有回答者，这是**设计缺口而不是配置问题**。「严禁编造」只允许三条正当出路：真问、诚实标未知、显式降级。而工具失败却带着未填字段继续走、产出建立在空字段上的稿子，是第四条错路，**比功能缺失更糟**。因此保护不能指望模型自觉停在第三条路，而要由程序结构性保证（硬失败或显式降级）。

## 判据必须从装配根走

「没人提供依赖」这类缺口要查**声明与装配两张皮**：声明了（配置项/字段/接口存在）不等于装配了（运行时真传进来）。判据须走装配根全程，**在用例里注入替身不算接线**——那只是测试亲手补上了缺失的那一跳，见 接线类缺陷只能靠「从外部观察真实装配根」的判据抓到 与 判据查「结果怎么来的」不只查「结果长什么样」。

## 一个字段背后常常是一次交接，不是开关

接线前先分清「开关」与「交接」。把政策取证字段硬接成「不调 retriever.search」，等于把「不做政策取证」实现成「不许查任何资料」；真实形状是内容包要求、代码不派、产物名在代码里根本不存在——那是一次独立的角色交接，深度还随档位不同。逐条定性流程见 未接线排查：扫四种形状、逐条人工定性、判据先注入证伪。

## Sources

- 三层各自齐备、缺中间层则「接好线也是空转」，以及「无界面无人可答是设计缺口、第四条错路比缺功能更糟」的判断，见 正听项目未接线专项排查与第二轮检查记录：其中记载 grep 提示词层对提问工具名零命中，故「要问」已声明而「用什么问」与「程序能问出去」两层皆断，接上回调后模型仍不提问。
- 「没人提供依赖要查声明与装配两张皮、判据必须走装配根」这条方法论亦由同一份记录支持，其判据自身替被测对象回答问题因而永远绿，属 判据要断言可观测的行为差异，不断言表面特征或词面 所治的形态。
- 当日日记 2026-10-03 日记 的方法论条目复述了同一组结论，并补上反向案例：把政策取证字段接成「不调检索」等于禁止查任何资料，该字段背后实为一次独立角色交接。
